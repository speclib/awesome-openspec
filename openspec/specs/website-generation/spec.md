# website-generation Specification

## Purpose
Building the static catalog website from the entries dataset with search, sorting, theming, and language icons.

## Requirements

### Requirement: Static catalog site is built from the entries dataset
The site SHALL be generated by Astro from `entries.json` at build time, producing fully static output with no runtime data fetching. Repo entries SHALL render as cards showing name, description, star count, primary language, and relative last-push time; video and link entries SHALL render as list rows without star counts (videos show view counts when present). Archived repos SHALL show an "archived" badge.

#### Scenario: Repo card
- **WHEN** the built site renders a repo entry with 454 stars
- **THEN** the card displays the star count, links to the repository, and shows its description

#### Scenario: Plain link row
- **WHEN** the built site renders a `link` entry (e.g., the Discord invite)
- **THEN** it appears as a row with name and description, without any star count

#### Scenario: Video row with views
- **WHEN** a video entry includes a `views` value
- **THEN** the row displays a formatted view count

### Requirement: Client-side search filters all entries
The site SHALL provide a search input that filters entries client-side by case-insensitive substring match on name and description, across all sections, updating results as the user types without page reload.

#### Scenario: Search narrows results
- **WHEN** the user types "superpowers"
- **THEN** only entries whose name or description contains "superpowers" remain visible

#### Scenario: Empty search
- **WHEN** the search input is cleared
- **THEN** all entries are visible again

### Requirement: Multiple sort orders for repo entries
The site SHALL offer sort controls with at least: stars descending (default), name A–Z, and recently pushed. Sorting applies to repo entries; video and link entries keep their section order regardless of sort.

#### Scenario: Default order
- **WHEN** the site loads
- **THEN** repo entries within each section appear sorted by stars descending

#### Scenario: Switch to A–Z
- **WHEN** the user selects the A–Z sort
- **THEN** repo entries re-order alphabetically without a page reload

### Requirement: Section filtering
The site SHALL provide section filter controls (e.g., chips) that limit the visible entries to one section or show all sections.

#### Scenario: Filter to one section
- **WHEN** the user selects the "UIs" filter
- **THEN** only UIs entries are visible

### Requirement: Light, dark, and system theme modes
The site SHALL offer a three-state theme toggle — light, dark, and system — persisting the choice in localStorage and applying it before first paint to avoid a flash of the wrong theme. In system mode the theme SHALL follow `prefers-color-scheme`.

#### Scenario: Explicit dark mode persists
- **WHEN** the user selects dark mode and reloads the page
- **THEN** the page renders dark from first paint

#### Scenario: System mode follows OS
- **WHEN** system mode is active and the OS switches to dark
- **THEN** the site switches to dark without user action

### Requirement: Language icons on entries
Entries tagged `language_tag: "zh"` SHALL display a Chinese-language indicator icon; entries tagged `"en"` SHALL display an English indicator or no icon per design. The stripped-marker description SHALL be shown (no raw `(Chinese)` text).

#### Scenario: Chinese entry indicator
- **WHEN** a repo entry has `language_tag: "zh"`
- **THEN** its card shows the Chinese-language icon and no literal "(Chinese)" text

### Requirement: Last-updated timestamp
The site SHALL display the dataset's `generated_at` timestamp (absolute or humanized) so visitors can see data freshness.

#### Scenario: Freshness visible
- **WHEN** the site was built from a dataset generated at time T
- **THEN** the page shows T as its "last updated" indication

### Requirement: Correct asset paths under the project base path
The site SHALL be configured with the base path `/awesome-openspec` so that all internal links and assets resolve correctly at `https://speclib.github.io/awesome-openspec`.

#### Scenario: Deployed asset resolution
- **WHEN** the deployed page loads at the project URL
- **THEN** all CSS, JS, and internal links resolve without 404s
